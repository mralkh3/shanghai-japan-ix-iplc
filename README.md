# 沪日 IX 专线

如果你正打算从上海方向访问日本业务，搜索到「沪日 IX 专线」基本离不开这几个问题：它到底是什么线路，和沪日 IPLC 差在哪儿，要怎么连进去，套餐价格多少钱，以及前置要付出什么代价。Mkcloud 把这条线路放在「沪日上云互联优化专线（IX）」目录下，交付形态和沪日 IPLC 类似，但接入入口完全不同。继续往下看之前，先把这几个核心差异搞清楚，能少走很多弯路。

## 一、沪日 IX 专线到底走的是什么路径

沪日 IX 全称「沪日上云互联优化专线（上海-日本 IX）」。它的"入口"不是宽带运营商，而是经过"上海互联网交换中心"（SHIXP）等 IX 交换中心的云厂内网地址。只有挂载到 SHIXP 的网络才能直接连入入口 IP——阿里云、腾讯云、百度云国内全网，火山云、华为云、UCloud 华东方向都属于这个范围。电信、移动、联通的家庭宽带或办公宽带是进不去的。

出口则稳定在日本 BGP，运营商侧接入了 PCCWG、NTT、Cogent、Lumen、Telstra、HE、Voxility 等多家国际路由，同时对接 Equinix IX、JPIX、BBIX、JPNAP 等日本本土交换中心，以及针对 Google、Cloudflare、Valve、SGGS 的私有 PNI。Mkcloud 给出的端内参考延迟为 25~28ms，这是入口 IP 到出口 IP 之间的专线段，加上云厂前置到用户本机的"前置段"和出口到目标平台的"后置段"才是实际 RTT。

每台 VPS 分配 1 个独立入口 IP 和 1 个独立出口 IP，分别是独立 IPv4 地址；出口不支持外部连入，不能当作公开网站托管、支付回调或游戏服务端使用。

这条线路对 Mkcloud 来说不是新品。在知识库公告里，他们明确沪日 IX 是「第一家发布以及售卖的 IXP 专线商家」的产品，定位是给已有云厂资源的用户提供「比直连专线更便宜、流量更大」的入口路径。

## 二、谁适合沪日 IX，谁其实不该选

判断值不值得买，先看自己的真实场景。

适合沪日 IX 的典型需求包括：办公或工作室已经有阿里云、腾讯云、火山云等云厂主机，希望把特定的出向流量统一通过日本的 BGP 出口走；做日本方向的店铺后台、协作工具调用，需要一条相对干净的日本出口；持续传输业务希望把月流量做大而不是被按月重置计费卡喉咙；或已经有云厂前置机器，目的是规避公网环境下的通报与扫描问题。

不太适合的情况包括：本地宽带或办公网络想直接拨号连入，这在线路层面就过不去；预算非常敏感且短期使用，月付价格相比正常沪日 IPLC 不一定便宜多少（IX 走的是云厂前置 + 专线段的两段成本）；不接受任何业务中断或对稳定性有极高要求，这条线路默认无 SLA 保障；以及用途属于「机场」「回国」等违法违规领域，全线都需要实名认证并严禁此类用途。

另外两个时间点值得注意。沪日 IX 在 2025–2026 年间有过多次运营商维护通知，包括 2026 年 4 月、5 月、6 月、7 月的架构升级和 IP 变更，期间业务可能中断 10~60 分钟；同年阿里云曾因整改需求短暂切断过"上海 IX"和"深圳 IX"方向的流量，已开机的存量 IX 用户虽然不受直接影响，但整改触发说明了这条线路对前置云的合规状态高度依赖。

## 三、沪日 IX 和沪日 IPLC 的真实差异

搜索沪日 IX 时，最常被同时提起的就是沪日 IPLC。两者都是上海到日本的跨境专线，但在接入方式、合规边界、价格结构和适用人群上有明显区别。

| 对比维度 | 沪日 IX 专线 | 沪日 IPLC 专线 |
| --- | --- | --- |
| 入口网络 | SHIXP 等互联网交换中心云厂内网 | 上海电信、上海 BGP 等省份直连 |
| 连入限制 | 必须通过支持的云厂主机连入 | 绑定一个省份，仅允许该省 IP 连入 |
| 出口 | 日本 BGP，多家国际运营商 + 多个 IX + PNI | 日本 BGP，同上体系 |
| 端内延迟 | 25~28ms | 25~28ms |
| 是否暴露公网 IP | 入口为内网地址，不暴露公网扫描面 | 入口为公网 IP |
| 前置成本 | 需自行准备云厂机器（轻量或按量计费） | 仅需入口省份的 IP 即可直连 |
| 默认 SLA | 不提供；故障需走工单 | 不提供；故障需走工单 |

简而言之，IPLC 偏向「即开即用、入口直连」，适合本地固定省份、有公网入口需求的用户；IX 则偏向「需要云厂前置、追求内网隐蔽」的用户。本地办公网络想稳定用一段时间，先看 IPLC；已经有云厂机器做配套，再看 IX。

## 六、上手沪日 IX 之前的前置准备

沪日 IX 的"看上去即买即用"其实有个常被忽略的前提：必须先有一台可达 SHIXP 的云厂主机，把它当作入口跳板。下面是常见的最小可用配置。

**1. 选一台云厂主机作为前置**
阿里云轻量应用服务器、腾讯云轻量、华为云耀云、火山引擎 ECS 都行。关键要求是机房在华东或华南（上海入口优先华东），带宽至少 200Mbps，并能和 Mkcloud 给出的入口 IP 在同一路由可达范围。火山引擎按量计费的实例带宽较高（约 0.8 元/GB 流量成本），适合做前置但长期使用不算便宜；阿里云、腾讯云的轻量实例（例如腾讯云上海锐驰型）有 200Mbps 标称带宽，但社区也有反馈实际带宽可能被限制到 20Mbps 甚至 1Mbps，下单前建议确认当前是否仍可购买。

**2. 实名认证 + 省级白名单**
Mkcloud 全线产品都要求中国身份信息实名，并采用「省级白名单」措施：购买时需选择允许连入的省份，开通后只能由该省份的 IP 经云厂前置连入。后续可在控制台调整省份，但不能在同一订单内更换地域。

**3. 连接方式与系统选择**
机器开通后拿到入口 IP，使用 SSH 或 RDP 连接；在 VPS 内运行日本方向的业务程序，流量会从独立出口 IP 发出。系统从 Ubuntu 20.04 到最新的 Debian 13、CentOS Stream 9、Rocky 9 等都可选，重装和升降级通过工单处理。

**4. 测试方法**
测试时建议把链路拆成三段：本机/办公室到云厂前置、云厂前置到 MK 入口 IP、MK 出口 IP 到目标日本平台。每段分别记录延迟、丢包和长时间稳定速率，再综合判断实际可用性，而不是只看一个总的 RTT 数字。

## 七、常见疑问与维护动态

**Q1：沪日 IX 套餐支持 IPv6 吗？**
现有公开资料对所有套餐的 IPv6 支持表述不完全一致。如果业务对 IPv6 有硬要求，下单前建议直接咨询客服确认对应 SKU，不要假设默认开启。

**Q2：海底光缆故障会不会影响这条线？**
理论上可能。Mkcloud 明示多运营商出口不等于跨境线路有独立备份，也不对中断时长作书面承诺。高可用业务需要自己评估故障容忍度。

**Q3：2026 年这条线还有在卖吗？**
从 Telegram 通知群历史来看，因 IX 产品需求量激增，Mkcloud 曾宣告 IX 产品"已全部售罄，等待扩容完成后再行开放"。当前在线状态以商店页面的"是否有货"判断为准，特定 SKU 暂时缺货属于正常现象。

**Q4：能开面向公网的服务吗？**
不能。出口不支持外部连入，主要用于访问日本方向的店铺后台、协作工具、研发与持续传输等出向流量，不适合用作公开建站、游戏服务端、支付回调或邮件接收。

**Q5：业务中断了怎么办？**
默认不提供 SLA。最近期的几条官方维护通知显示，2026 年 4 月至 9 月间，沪日/沪美/沪港 IPLC 与 IXP 产品经历了多轮运营商割接、IP 变更和安全补丁升级，最长单次中断约 60 分钟。建议持续运行的业务保留降级方案或在前置云上做兜底。

**Q6：最低门槛多少？**
按知识库公告参考价，沪日 IX 当前最便宜的可购档是 1TB / 200Mbps，月付参考 166 元/年付 1188 元；考虑到需要云厂前置（轻量主机通常几十元/月起步），整体起步成本会比纯沪日 IPLC 高一些，但月流量和带宽上限也更高。

## 八、选择建议：什么情况下选 IX，什么情况下选 IPLC

- 你已经在用某家大厂的华东或华南云主机（含轻量、ECS、按量付费），希望「出口日本」走专线段而不是公网 → 沪日 IX 通常更划算。
- 你的入口是家庭宽带、办公宽带或固定机房，需要即开即用、本地直接拨号 → 直接选沪日 IPLC，省掉前置成本。
- 你有持续大量上传任务，对月流量敏感 → 看 IX 的 2TB / 3TB / 6TB 套餐，性价比和传统沪日 IPLC 比会拉开差距。
- 你对延迟到 1ms、3ms 这种数量级敏感，纠结毫秒级差异 → 沪日 IX 与沪日 IPLC 端内都是 25~28ms，没有本质区别，前置云和后置目标的影响更大。
- 你无法接受合规与封禁风险 → IX 入口走的是云厂实名网络下限，但本身仍要求实名和正规用途；2025–2026 年阿里云侧曾对上海 IX、深圳 IX 方向的流量做过整改切断，这种前置侧的变化不是用户能控制的，需要权衡。

把云厂前置费用、月流量档位、实名要求、维护中断这几项加总算一遍，再决定选哪条线，会比单纯看月付价格稳妥得多。
